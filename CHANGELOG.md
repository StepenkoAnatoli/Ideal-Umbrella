# Changelog

Notable changes to Ideal-Umbrella. `HISTORY.md` is the narrative history and `research/progress-log.md` the full work log; this file is the short summary.

## [Unreleased]
### Added
- `config/uninstall.py` (with `--dry-run`): undoes `config/install.py` from the install record, restoring earlier values and the CLAUDE.md backup.
- `config/install.py` writes `~/.claude/ballast/install-record.json` with what it added or replaced.
- `IDEAL_UMBRELLA_TAIL_BYTES` for how much of the transcript end `hooks/context_check.py` reads.
- `scripts/unused_tools.py`: tool-call counts from transcripts, flags denied tools that were used.
- GitHub Actions: pytest, the keyline suite and a JSON check on Ubuntu and Windows.

### Fixed
- `keyline/keyline_hook.py`: a dotfile under `notes/` or `plans/` (`.gitignore`, `.DS_Store`) is not a note; `--watch` without a pattern, or any other flag, is one stderr line and exit 1 instead of a silent fall-back; a note or rendering that is not UTF-8 is one stderr line with the file name and exit 1 (a not-UTF-8 rendering is no longer blamed on the note); when only the rendering check fails the header names the rendering to fix, not the note; `.he.md` is a rendering too, a note is checked against every rendering it has, and two notes beside one rendering are a finding of their own, from whichever of the files is written (the first line says to keep the one it renders; the checks wait until one note is left); a `--watch` pattern that spells the dot (`notes/.todo.md`, `notes/.*`) names a dotfile, while `notes/*` does not, as in a shell (the dotfile rule applied before the patterns, and fnmatch's `*` would match the dot); a file name that is not UTF-8 is a backslash escape in the one stderr line, not a traceback (`reconfigure(encoding=...)` had reset `errors=` to strict).
- `keyline/measure.py`: a named file that cannot be counted, or a folder with nothing to count, is an error (exit 2); a tiktoken data failure is one line, exit 1; a symlinked sub-folder, on Windows a junction too, prints a skip line instead of vanishing; the unreadable-file skip now has a test.
- `scripts/usage_breakdown.py`, `scripts/unused_tools.py`: an unreadable transcript is one stderr line and the others are still counted. `scripts/usage_breakdown.py`, `scripts/toolresult_share.py`, `scripts/usertext_split.py`, `scripts/usertext_top.py`: wrong-typed transcript fields (a `usage` list, an `id` list, a null `text`, a non-string role) are skipped; a UTF-8 BOM is accepted in transcripts, `user-settings.json`, `plugin.json` and `.mcp.json`.
- `scripts/plugin_cost.py`: an output folder that does not exist, or a tiktoken load failure, is one line and exit 1; plugins under a hidden intermediate folder (`.plugins/cache/`) are counted; a folded or literal YAML indicator (`>`, `|-`) is stripped from the description.
- `keyline/keyline_check.py`: every kind but a date, a time and a timestamp is now looked up by extraction, as numbers were, so a path, file name, proper noun, identifier or hash is not found inside a longer token of the rendering (`notes/a.txt` in `notes/a.txt.bak` or `notes/a.txt/`, `report.pdf` in `report.pdf.gpg`, `Jean-Luc` in `Jean-Luc-Picard`, `API` in `API.md`); a Hebrew prefix glued to a path (`ב-__tests__/`) and a name the rendering moves to a sentence start still count. A date and a time written as two tokens (`2026-10-25 14:30`) are present in the ISO form (`2026-10-25T14:30Z`); only the other direction was accepted. A hex digest of up to 128 digits (sha256, sha512) is one invariant; the hash rule stopped at 40, so a changed sha256 passed. A capitalised name with a Latin diacritic (`Zürich`, `Léa`, `Øyvind`, `São`) is a proper noun; it was not extracted, or cut (`Caf` for `Café`), so a swapped name passed. A URL is one invariant with its scheme (`https://example.com/a/b`); it was extracted as the path `//example.com/a/b`, so `https` -> `http` passed. An all-caps month or weekday name longer than three letters (`OCTOBER`, `MONDAY`) accepts its Hebrew form; `DEC` and `SAT` stay acronyms. `No. 5` is a number sign, not a negation (a Hebrew `מס' 5` used to fail with "1 lost"), and a label `May:` is the month, not a possibility hedge. A list marker has at most three digits (also for the lint's numbered-item rule), so `2024. Migration done` keeps the year.
- `keyline/keyline_check.py`: the left token boundary takes the same Latin letters as the right one, so no token starts inside a word (`the ÉCOLE` gave the identifier `COLE`, `école/notes.txt` the path `cole/notes.txt`, and a swapped name passed) and a long run of diacritic pairs is extracted in linear time (16000 `Zé` pairs before `_`: 0.003 s, was 24 s against the hook's 30 s timeout). A file name or path may again start with a Latin letter with a diacritic or a Hebrew letter (`Übersicht.md`, `סיכום.md`, `תיקיה/קובץ.txt`); the linear-time fix had made the first character ASCII, so a swapped Hebrew name passed. An all-caps name with a diacritic (`ÉCOLE`, `NGUYỄN`) is an identifier. `no.` at the end of a line before a numbered item, a date or a time on the next line is a negation (`No. 5` is not), and `May` before a number on the next line is the modal. Sentence punctuation after a URL (`https://x.y/z:`, `?`, `!`) is not part of it. A time with seconds is present in an ISO timestamp that adds fractional seconds (`14:30:00` in `2026-10-25T14:30:00.000Z`), a timestamp without a zone in one that adds `Z`; a dropped zone or fraction stays a miss.
- `keyline/keyline_lint.py`: a `keyline-allow.txt` line with several words allows each of them; it used to become one entry that never matched.
- Docs: `keyline/README.md` describes matching by extraction and its edges, names non-ASCII names and long digests in Honest limits, and no longer names one machine's corpus for the lint measurement.
- `config/install.py` and `config/uninstall.py` refuse an install record with a wrong-typed field (`added_keys`, `replaced`, `deny_added`, `installed`, `created`, `claude_md`, `uninstalled`, `claude_md.sha256`) before anything is written, instead of crashing after `CLAUDE.md` was replaced; a record with a UTF-8 BOM is read, and a record that is not UTF-8 is named. They refuse a read-only `CLAUDE.md`, `settings.json`, hook or record before the first write, so no backup or hook is left behind (`config/add_to_repo.py` does the same for a read-only `settings.json` or hook before the hook is copied, and gained tests for symlinked targets and for the temp file being removed when the rename fails).
- `config/install.py` records the `CLAUDE.md` change and its backup before `CLAUDE.md` is written, so an interrupt between the two no longer leaves a `CLAUDE.md` the next install calls "not written by this install"; it says when a record from before the content hash made it back up a `CLAUDE.md` it could not tell from the template, and what uninstall will do; its docstring describes the current write order.
- `config/install.py`: the interim record written before `CLAUDE.md` carries no `settings.json` data, nor the marker an uninstall leaves, so an install interrupted at its last write no longer leaves a record that says nothing was added while `settings.json` holds the two keys, or one the uninstall reads as neither unfinished nor absent; `config/uninstall.py` treats such a record like no record for the settings and says so. A `CLAUDE.md` backup whose record could not be written is removed again, and a backup an interrupted install recorded is reused by the next install when it still equals the file, so an interrupt leaves no orphan `CLAUDE.md.bak-*`.
- `config/install.py`, `config/uninstall.py` and `config/add_to_repo.py` refuse a read-only folder a write or a delete needs (`.claude`, `ballast/`, `hooks/`, the home folder, the state folder and its sub-folders) before the first write; the hook used to be written and the next file to fail. `config/uninstall.py` clears a Windows read-only attribute on the hook, log, backup, `CLAUDE.md` or a file inside the state folder before deleting it. The checks see a POSIX mode or the Windows read-only attribute, not a Windows ACL.
- Every script that reconfigures stdout (or stderr) to UTF-8 keeps `errors="backslashreplace"` on it (`reconfigure(encoding=...)` alone resets the handler to strict), so a path or file name that is not UTF-8 is an escape in the output, not a `UnicodeEncodeError`; `tests/test_source_rules.py` checks every such call.
- `config/uninstall.py` restores the `CLAUDE.md` backup when `CLAUDE.md` was deleted after the install; keeps the recorded `settings.json` values in the record and says so when `settings.json` is missing, instead of dropping them; reports a replaced key that was removed after the install, with its earlier value; and leaves `CLAUDE.md` in place and reports it when the record's backup name is not a plain file name, instead of deleting it.
- `keyline/keyline_check.py`: a bare number is present only when the rendering's own extraction yields it, so it is not found inside a date (`10` in `2026-10-25`, on any of the three positions), a percentage (`10%`) or a slash pair (`10/25`), while a year range (`2020-2024`) and a dash-joined number (`FY2024-25`) still pass against themselves; a time is not found at the end of a longer time (`00:30` in `10:00:30`) and is not extracted there either (`3:1:30` is three numbers); a number alone on a line (`10.`) is a number, not a list marker; an all-caps identifier (`DEC`, `SAT`) is not accepted in a Hebrew month or weekday form. A long dash-joined run is extracted in linear time (16000 `ab-` pairs: 0.3 s, was 16.5 s against the hook's 30 s timeout).
- `keyline/keyline_lint.py`: the word cache is written whole or not at all (temp file and rename) and is rebuilt when its `; N words` header does not match the lines present; a truncated or empty cache used to make every ordinary word an "abbreviation". A word tiktoken counts as one token is never reported; a word outside the list that could not be counted is reported as "not counted" with the cause (tiktoken missing, or its o200k_base data not loadable), not as "not one token". A rebuilt cache keeps the mode a plain write gives, not the temp file's private mode, without reading the process umask (which can only be read by setting it).
- `keyline/measure.py` skips a file it cannot read (a dangling symlink) with one line instead of a traceback.
- `config/add_to_repo.py` copies the hook before writing `settings.json` and lists what it wrote before an error, as the other installers do.
- `config/install.py`: `--verify-only` reports a `hooks.UserPromptSubmit` that is not a list as one line instead of a traceback; verification warns when a Windows hook path holds a character bash changes inside double quotes (`$`, a backtick, `\\`); `CLAUDE_CONFIG_DIR`, when set and `--home` is not given, is where the files are installed and verified, and `hooks/context_check.py` keeps its state folder and log there too (both read it with `~` expanded and the path made absolute).
- `config/uninstall.py` removes `ballast/state/` (unlinked when it is a symlink or a Windows junction, not followed) and `ballast/context_check.log`, and a backup name with a path separator in the install record no longer crashes the undo after the settings were rewritten.
- `config/verify-tokens.py` reports a tiktoken failure once and exits 1 instead of printing "Error reading" for every file and exiting 0; no API count at all is also exit 1.
- `scripts/usage_breakdown.py` finds the transcripts in a folder whose name holds `[`, `*` or `?`.
- The keyline suite starts its scripts with `-I`, as the CI comment and the docs say. `tests/test_source_rules.py` gained two rules: a `glob.glob()` goes with `glob.escape()`, and a test that starts a script passes `-I` among its leading flags (a `-m` module run is not a script run; `-X`/`-W` take an argument).
- Docs: "no extractable invariant" is `INCONCLUSIVE` only when the source has no hedge either; `pnpm` is on the keyline lint's built-in allow list; the keyline hook's exit 1; hard-linked user files are replaced by a new file on install.
- `tests/test_install.py`: the temp-file cleanup test now reaches the cleanup as any user (it used to pass as a non-root user without running it).
- `keyline/keyline_check.py` extracts the identifier shapes that fell through every rule and let a rendering drop them unnoticed: plural acronyms (`PRs`), bare `v2`, git hashes with a digit (`b07b3b6`), lowercase words with a digit (`sha256`, `utf8`), dunders (`__init__`). A bare number no longer counts as present inside a time or a grouped number (`10` in `10:00`, `2` in `2,500`). A name after a mid-line dash, `>` or `**bold:**` label is checked (`- **Stack:** Postgres` used to skip `Postgres`). Hebrew hedge words (עלול, ייתכן, כנראה, צריך, אמור, יכול, ניתן, with inflections and prefixes) keep the hedge class, so a correct Hebrew rendering no longer fails with "hedges lost"; and a month or weekday name is accepted in its Hebrew form (`Monday` as `ביום שני`, `October` as `מאוקטובר`). An all-caps `MAY` in a mixed-case line is the month, not a modal; a label value (`**Status:** Done`) is not a name; `__Bold__` emphasis is not a dunder; a Hebrew month name is matched as a word, not inside another word (`מאיפה` is not `May`).
- `keyline/keyline_hook.py` ignores a `notes/` or `plans/` file outside the project (`~/notes/todo.md` used to be linted, and could block with exit 2, from any project); a `notes/` folder that is a symlink into another folder is still watched.
- `config/install.py` verification fails when the Python the hook command names no longer exists (a deleted venv, a pyenv bump); `|| exit 0` hid that the hook never ran. A command written with `~` or `$HOME` is expanded first.
- `config/install.py`, `config/uninstall.py` and `config/add_to_repo.py` write every user file whole or not at all (temp file beside it, then rename): a write that failed part way (disk full) used to leave a truncated `CLAUDE.md` or hook file. On an error the installers list the backups and files written before it, so the backup of `CLAUDE.md` is findable. A file written for the first time keeps the mode a plain write gives it, not the private mode of the temp file (the kernel applies the umask; it is not read); a read-only target is refused, as before, instead of replaced. A hook file or install record that is a symlink to a missing target is reported before anything is written, as `settings.json` and `CLAUDE.md` already were; `add_to_repo.py` does the same for the repository's `settings.json` and hook instead of a bare `FileNotFoundError`.
- `config/uninstall.py` says when `permissions.deny` is not a list and keeps `deny_added` in the record, so a later run can still remove the tools; it used to skip the key in silence and drop the list.
- `keyline/keyline_lint.py` with the word cache present and tiktoken missing reports an abbreviation as "not one token" instead of stopping with the install hint (a regression of the hint fix: the exit escaped `token_count()`). A `keyline-allow.txt` or word cache that is not UTF-8 is a one-line read error, not a traceback; so is a cache path that cannot be read.
- `keyline/keyline_check.py` treats a capitalised `May` inside a sentence ("in May because") as the month, not a possibility hedge.
- `config/install.py` reports a file-system error or a bad `settings.json` met during verification (after an install or with `--verify-only`) as one line; `config/add_to_repo.py` does the same for a `.claude` that is a file or a read-only folder. A `settings.json` that is not UTF-8 is reported as such, not as "not valid JSON".
- `scripts/usertext_split.py`, `scripts/usertext_top.py`, `scripts/toolresult_share.py` and `config/verify-tokens.py` no longer crash on a file that is not UTF-8.
- Every script sets UTF-8 stdout before printing. `scripts/usertext_top.py`, `toolresult_share.py`, `unused_tools.py`, `lint_validate.py`, `plugin_cost.py` and `config/verify-tokens.py` used to stop with `UnicodeEncodeError` on a Windows console (cp1252) at the first non-ASCII user text, tool name, word, plugin name or file name; `-I` ignores `PYTHONUTF8`.
- `tests/test_source_rules.py` keeps three rules on every script: a `print()` to stdout needs `sys.stdout.reconfigure(encoding="utf-8")`, `sys.exit` only in `main()`, and every text read either passes `errors=` or handles `UnicodeDecodeError`.
- `keyline/keyline_check.py` extracts an ISO 8601 timestamp (`2026-10-25T10:00:00Z`) as one invariant; it used to split into two numbers and a time, so a rendering that changed the day or hour passed. A possessive (`Claude's`) no longer makes the `'s` part of the name, and `May 2026` is the month, not a hedge. A note that is not UTF-8 is a read error in one line, not a traceback: exit 2 in `keyline_check.py` and `keyline_lint.py`, exit 1 (non-blocking) in the hook.
- `keyline/keyline_lint.py` says how to install tiktoken when the word cache has to be built and tiktoken is missing; the hook used to show a traceback on every write of a watched note.
- `config/install.py` and `config/uninstall.py` refuse to run on an `install-record.json` that exists but is not valid JSON, instead of treating it as absent and overwriting it; a `settings.json` or `CLAUDE.md` that is a symlink to a missing target is reported before anything is written; output is UTF-8 so a non-ASCII home path cannot crash the listing on Windows.
- `config/uninstall.py` reports a file-system error during the undo as one line (a second run finishes the undo), tolerates a record whose backup name is not a string, and says why a template-matching `CLAUDE.md` the install never wrote is left in place.
- `hooks/context_check.py` fires again after a compaction that still lands above the threshold (the earlier band kept it silent until the next band), and its comment on `compact_boundary` now matches what Claude Code records (`postTokens`).
- Docs: `keyline/README.md` and `README.md` no longer describe one machine's venv, project folder and settings paths; the CI comment on `PYTHONUTF8` says what it covers (the `-I` children set UTF-8 output themselves).
- `scripts/toolresult_share.py`, `scripts/usertext_split.py` and `scripts/usertext_top.py` no longer crash on a transcript line that is a JSON list or string, print usage when run without arguments, and report an empty transcript instead of dividing by zero.
- `scripts/unused_tools.py` no longer counts a `tool_use` block without a name as a tool called `None`.
- `config/install.py` writes the install record after `settings.json`, so a failed settings write no longer leaves a record of values that were not installed.
- `keyline/measure.py` says how to install tiktoken when it is missing instead of raising ImportError.
- Docs: the keyline suite count (35 checks, 36 on Windows), one-machine paths in the keyline hook and test docstrings, and the CHANGELOG pointer to the history files.
- `scripts/lint_validate.py` and `scripts/plugin_cost.py` no longer hardcode one machine's paths: the keyline module and tiktoken cache come from this repository, and the corpus folder and Claude app folder are arguments (with per-OS defaults and `CLAUDE_APP_DIR`). Both print usage and fail cleanly on a missing folder.
- `scripts/tokentest.py` no longer redefines `claude` (the pyflakes warning is gone).
- The user-level hook command `config/install.py` writes now ends in `|| exit 0`. A `settings.json` synced to a machine without `~/.claude/ballast/context_check.py` (or without that Python) used to exit 2 there, which blocks every prompt.
- `config/add_to_repo.py` keeps a scalar value the repository already sets and reports it, instead of replacing it silently; `--force` replaces it. `merge()` now returns `(changes, notices)`.
- `scripts/usage_breakdown.py` no longer crashes on a transcript line that is a JSON list or string.
- `keyline/keyline_check.py` reports an empty source as `INCONCLUSIVE`; it used to `PASS` with 0 invariants.
- `config/install.py` verification fails when `permissions.deny` is not a list (a string used to pass by substring match), passes when the home path contains a quote, and reports a file-system error (for example `~/.claude/ballast` existing as a file) as one line instead of a traceback. The unused `verify_only` argument of `install()` is gone.
- `hooks/context_check.py` reads its stdin as UTF-8 regardless of the locale (a non-ASCII transcript path on a cp1252 Windows host was never matched), removes per-session state files older than 30 days, and trims its log past 1 MB.
- `config/verify-tokens.py` says how to install tiktoken when it is missing instead of raising ImportError.
- `config/uninstall.py` no longer deletes `CLAUDE.md` when the backup it should restore from is missing; it leaves the file, reports the missing backup, and keeps the record so a later run can still restore it.
- `config/install.py` verification no longer fails when you keep your own `autoCompactWindow` or `skillListingBudgetFraction` (left as is without `--force`); it prints a warning. A missing value still fails.
- `config/install.py` reads and checks everything before writing and writes `settings.json` last. A failed install (for example a non-UTF-8 `CLAUDE.md`) used to leave a hook entry pointing at a missing file, which blocked every prompt.
- `config/uninstall.py` run a second time no longer deletes your own values that match the template, or an identical `CLAUDE.md`: the record stays as an "uninstalled" marker. Without a record, keys are removed only when the Ideal-Umbrella hook is installed, and `CLAUDE.md` is backed up before it is deleted.
- `config/uninstall.py` compares against the values the install wrote (now kept in the record, with a hash of `CLAUDE.md`), not the current templates, so a `git pull` between install and uninstall no longer strands installed values or the `CLAUDE.md` backup. Anything left as is stays in the record.
- `config/install.py` and `config/uninstall.py` resolve `--home`, so `--home .` or a literal `~` no longer writes a relative hook path.
- `config/install.py`, `config/uninstall.py` and `config/add_to_repo.py` write through a symlinked `settings.json` or `CLAUDE.md` instead of replacing the link.
- A malformed hook entry (a hook that is not an object) no longer crashes install, uninstall or verify.
- Uninstall and verify no longer fail on a `CLAUDE.md` that is not UTF-8; uninstall leaves it as is.
- Reinstalling after editing `CLAUDE.md` or a setting by hand: uninstall now restores those edits, not the state before the first install.
- Re-running `config/install.py` after a `git pull` that changes a template value now updates a setting that still holds the value an earlier install wrote; it used to keep the old value unless you passed `--force`. Values you set yourself are still kept. Verification checks against the current template instead of hardcoded values.
- `scripts/unused_tools.py` exits with an error when the folder is missing or holds no transcripts, instead of reporting that no denied tool was used.
- Keyline test "absolute pattern matches backslash, other-case path" runs only on Windows; it failed on Linux and macOS, where backslashes and case are significant in paths.
- `keyline/keyline_check.py`: a capital letter followed by digits (`S3`, `A100`, `P0`) is an identifier (it used to be dropped with the lone letters `A` and `I`), and an exponent or hex number (`1e10`, `0x1f`) is one invariant, not two or three.
- `keyline/measure.py` skips a named pipe or socket in a walked folder with one line instead of blocking on it, and a file it cannot stat (a listed but unsearchable subfolder) with one line instead of a traceback; an argument it cannot stat is `error: cannot read ...`, exit 2. `keyline/keyline_hook.py` reports a file it cannot stat in one line, exit 1.
- `keyline/keyline_hook.py`: a word-cache error (a cache folder in the way, tiktoken missing) is reported as what it is, not as the note being unreadable; a `cwd` that is not a string in the hook event is ignored instead of crashing; the docs say that `--watch` patterns do not lift the suffix rule (a watched `.py` file is passed over).
- `scripts/plugin_cost.py` counts a description that holds a special token (`<|endoftext|>`) or starts with a BOM instead of stopping with a traceback.
- `scripts/toolresult_share.py`, `usertext_split.py` and `usertext_top.py` report a missing or unreadable transcript in one line instead of a traceback; `scripts/usage_breakdown.py` and `scripts/unused_tools.py` skip a folder whose name ends in `.jsonl`.
- `config/install.py` records the `CLAUDE.md` change (and its backup) before `settings.json` is written, so an install that fails on `settings.json` still leaves a record `uninstall.py` can restore from; a `CLAUDE.md` the installer wrote and the user has not changed is not backed up again when the template changes; the record's new `created` list names the `permissions`, `permissions.deny`, `hooks` and `hooks.<event>` containers the install made, and `config/uninstall.py` removes only those, keeping an empty container the user had before (a record from before the list existed keeps the old behaviour, also across a re-install and a second uninstall run; a re-install after a clean uninstall records what it creates, and does not take over a container the user made by hand in between).
