# Review of GPT Umbrella — 2026-11-17

Reviewed v0.1.0 from five perspectives: accounting, safe installation, runtime correctness,
performance, and the strength of the product claims. This was a structured self-review,
not an independent third-party audit. Those fixes were made in v0.1.1. The repository
integration is v0.1.2 and additionally fixes Unicode CLI output; see [validation](validation.md).

## Confirmed findings and fixes

| Priority | Perspective | Reproduction and consequence | Fix |
| --- | --- | --- | --- |
| P1 | Installer safety | Adding an unrelated file path and its checksum to a corrupted install manifest caused uninstall to delete that file within Codex home. Tested with a disposable sentinel. | Validate a fixed ownership allowlist, required records, checksums, marker structure, and backup namespaces before writes. |
| P2 | Runtime | Forks sharing a root session ID shared reminder state, suppressing one another's reminders. | Identify reminder state by canonical transcript path. |
| P2 | Runtime | A saved high request count overrode a newer low transcript reading. | Remove the saved-usage override and per-request collector. |
| P2 | Runtime | A compaction followed by another high-context reading in the same band did not reset the reminder. | Track the most recent visible compaction boundary fingerprint. |
| P2 | Accounting | Legacy cumulative usage after a model switch was attributed entirely to the final model and could be priced at its rate. | Mark mixed legacy attribution unknown and withhold model-specific pricing. |
| P2 | Robustness | A non-string tool-call ID caused a TypeError instead of a useful analysis report. | Validate IDs, skip malformed records, and count warnings. |
| P2 | Reporting | The last context estimate remained visible after compaction even when no post-compaction measurement existed. | Clear it to unknown. |
| P2 | Evaluation | Smaller per-response averages could hide more total work. | Show total tokens by category, response counts, and averages together; flag source warnings and differing model sets. |
| P3 | API advice | A plain string input with previous_response_id was incorrectly treated as possible replayed multi-message history. | Apply the heuristic only to arrays with multiple items. |
| P3 | API advice | Functions inside a namespace were omitted from eager-tool counts. | Count nested namespace functions with shape/depth checks. |

All ten cases were reproduced against the original version: eight assertion failures and
two errors. They now pass. Four further regression checks cover mutation exclusion,
preserving an external edit during rollback, invalid backup paths, and invalid rate objects.

## Additional safety and performance changes

Install and uninstall now acquire an exclusive mutation lock, check for concurrent file
changes, and avoid overwriting external edits during rollback. This does not lock other
applications out of the filesystem or eliminate every possible filesystem race. After a
hard crash, a stale lock requires inspection before removal.

The new version installs just `UserPromptSubmit`, removing the per-request process
launch. It reads the bounded transcript tail at prompt time.

## Independent arithmetic check

Using a separate summation of distinct response IDs, both available local JSONL snapshots
matched the analyzer's input, cached input, and output totals. The completed log matched
its cumulative counter. In the active log, the counter lag was exactly the most recent
response, which had arrived before its matching counter event. The warning remains because
other mismatches can indicate missing history or unsupported formats.

## Remaining limitations

- **Live activation:** synthetic installed-hook execution passed on Windows. Automatic
  execution depends on local Codex hook discovery and trust; file verification cannot
  establish activation on another installation.
- **Savings and quality:** the 6,000/5,000-token budgets are experimental starting values.
  No matched task benchmark proves reduced cost, lower latency, or preserved correctness.
- **Coverage:** available JSONL is not all account history. Remote and paginated history are
  excluded; legacy cumulative records cannot deduplicate shared fork ancestry.
- **Context monitor:** transcript formats are unstable. A missing usable window suppresses
  the reminder, and a compaction boundary outside the bounded tail may not be observable.
- **Privacy:** output reports omit raw commands and tool results, but include IDs, paths,
  tool/model names, and deterministic fingerprints. Fingerprints are not strong anonymization.
- **Platforms:** Windows tests passed. Other operating systems remain untested here.

Assessment: a tested prototype with repaired defects. Effectiveness still requires a live
smoke test and matched quality/latency/usage measurements. Do not present it as a proven
cost optimizer or use estimated API prices as subscription quota savings.
