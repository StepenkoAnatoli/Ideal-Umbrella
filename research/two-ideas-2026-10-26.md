## Decisions and why
- Savings line as systemMessage only: the user sees the saving and the model pays nothing; the hand-off note stays in additionalContext because the model must act on it. Both share one JSON object.
- `first-pass:breaker` is not installed: emulated with a fresh-context general-purpose agent with a breaker brief, plus the `code-review` skill at high.
- The template is copied by `add_to_repo.py` only, never by `install.py`: a learnings file belongs to a repository.
- No floor cache in the state file (round 1 #5, round 2 CR6): the state file is dropped below the threshold; the head read is short and bounded.
- Learnings file is a courtesy: its failure never fails the run (round 2 B1).
- A low `IDEAL_UMBRELLA_TAIL_BYTES` hiding the line is documented, not overridden (round 2 B4).
- The link walker is a step-by-step resolver, not per-case patches (round 7 H7: each round's patch missed the next layout); it judges leaving the repository on disk, not from link text (round 8 K2).
- Test link targets use `os.path.join`: Windows cannot follow a "/" target (round 9 M1).
- Two resolvers stay (realpath for the file, the walker for links): both walk the disk, a merge has no failing case (round 8 K6 rejected).
- Running add_to_repo on a subfolder of a repository is out of scope (round 5 E6: behaviour already on main).
